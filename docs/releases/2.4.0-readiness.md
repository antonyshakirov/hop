# Hop 2.4 release preparation

This document is a preparation checklist, not release approval or evidence of publication.
Owner acceptance resumed on 28 October 2026. Completed probes remain accepted; public version remains unchanged.

## Prepared

- Input source list: separate persistent pin/hide preferences, collapsed Other Sources,
  restore inside the expanded list, no hidden footer, selected-source protection.
- Confirmed agent pin/hide actions and source-list state; existing confirmation and
  replay rules remain required. Presentation operations never request audio access.
- Updated Sound guide in all 22 languages; short onboarding/news copy and existing
  illustrations preserved. `2.4.0.md` is the prepared English GitHub release body.
- Website Sound scenarios and localized screenshots are prepared separately; they
  require final browser acceptance before publishing.

## Before public release

1. Confirm installed Dev version and run the saved manual acceptance list below.
2. Website browser acceptance completed: Sound section and guide passed in all 22
   languages at 320/375/390/768/1440/1920 px (264 cases), including actual line ranges,
   copy and overflow. The canonical website gate must match the final copy commit.
3. Align CHANGELOG and localized docNews release dates with the actual publication
   day; do not assume the preparation date of 22 October is the publication date.
4. Freeze the exact release source, run the canonical full release gate including
   CodeQL, then verify its proof. The previous CodeQL tool/SDK was removed after
   its authorized one-off use. Reuse an existing installation if available; a new
   large download needs separate authorization. Native-only checks do not replace it.
5. Run the existing 2.4.0 release pipeline: signed universal app/helpers,
   notarization/stapling, archives before update metadata, verified site/tap update,
   and only then the tag and GitHub release. Use the existing rollback contract.

## Accepted live checks

- MacBook and AirPods input startup: controls become available together and capture
  stops when Sound closes. The owner confirmed both.
- Hop Mix appears as an input on Start and disappears on button Off or Sound close.
  Two live cycles verified CoreAudio device counts of 1, 0, 1, 0.
- The owner observed a live Hop Mix level in Zoom. Empty still screenshots did not
  establish a voice failure. A later interrupted receiver setup is incomplete and
  does not invalidate that observation.
- Disconnected input names are readable in installed Dev; 32 targeted source-list,
  preset and audio-agent tests passed. The earlier 2081-test full native result
  belongs to the preceding source and does not replace the final release gate.

## Remaining manual checks

- With the input mixer off: pin/unpin, hide and restore an inactive source; close
  and reopen/restart. Source choices, gain/mute and the system microphone stay intact.
- Many sources: expand/collapse, resize, scroll and restore-list height; no empty
  window space. Verify buttons retain their hand cursor.
- Audio: voice plus music received by a consumer using Hop Mix; live macOS default
  microphone changes; AirPods accessory mute and status synchronization.
- Output: master volume across app-specific destinations, disconnect/reconnect with
  no unexpected fallback to speakers, and mixer on/off without a sudden level jump.
- Full-screen app: Hop Dev opens above it and stays anchored when the menu bar hides.

Prepare the receiver completely before requesting speech. Do not reopen Zoom or
repeat an accepted speaking probe by default. Every new physical microphone probe
needs a fresh readiness reply and a separate cue before a short bounded capture. Do not infer physical acceptance from synthetic PCM/UI tests.
