# Закрыть приложения: прототип

## Поведение

Пользователь открывает список работающих GUI-приложений и закрепляет те, которые должны остаться открытыми. Кнопка в строке завершает одно незакреплённое приложение. Общая кнопка отправляет такой запрос всем незакреплённым приложениям из текущего списка. Само открытие модуля ничего не завершает.

Закрепления сохраняются по bundle identifier в UserDefaults, ключ `appQuitPinnedBundleIdentifiers`. Они действуют на все экземпляры приложения и переживают его перезапуск. У приложения без bundle identifier закрепление недоступно. Hop, его известные варианты с идентификаторами `com.antonshakirov.minimo*` и `com.antonshakirov.hop*`, текущий процесс и Finder исключены из списка. Приложения с activation policy accessory/prohibited также исключены.

## Документы и результат запроса

Используется только `NSRunningApplication.terminate()`. Приложение само обрабатывает обычный выход и сохранение документов. Hop не выбирает ответы в диалогах сохранения, не меняет настройки autosave и не вызывает принудительное завершение. Гарантировать сохранение данных сторонним приложением Hop не может.

Возвращённое `true` означает отправленный запрос, а не завершившийся процесс. Строка остаётся в списке до реального завершения. Пользователь может сохранить документ, отменить выход или повторить запрос. Отмена в одном приложении не отменяет уже отправленные запросы другим приложениям. При `false` строка показывает отказ отправки и также остаётся в списке. Автоматического повтора и таймера принудительного завершения нет.

Источник контракта: [Apple: NSRunningApplication.terminate()](https://developer.apple.com/documentation/appkit/nsrunningapplication/terminate()). В sandbox вызов не может завершать сторонние приложения; ошибка отправки отображается как отказ.

## Технический контракт

- `AppQuitApplication` и `AppQuitPolicy` в HopCore описывают процесс, идентичность запуска, фильтрацию и исключения.
- `AppQuitController()` создаёт нативный backend; `backend`, `defaults`, собственные PID/bundle ID и `preview` можно передать явно.
- `refresh()`, `setPinned(_:for:)`, `quit(_:)`, `quitAllUnpinned()` — действия контроллера.
- `applications`, `pinnedBundleIdentifiers`, `requestStates`, `unpinnedCount` — состояние для интерфейса; `isPinned(_:)` проверяет исключение.
- `AppQuitView(controller:strings:)` — самостоятельный экран. `AppQuitStrings` требует `title`, `quitAll`, `quit`, `pin`, `unpin`, `cannotPin`, `documentNotice`, `empty`, `requested`, `refused`. Все тексты передаются интеграцией; встроенной таблицы переводов нет.
- Шрифты, цвета и hover используют `Theme`. Направление текста и выбранный язык задаёт общая оболочка Hop.
- `NativeAppQuitBackend` читает NSWorkspace и обновляет список по launch/terminate/activate notifications. Перед каждым запросом контроллер снова проверяет список и закрепления, а backend сверяет PID, дату запуска, bundle ID и путь. Запуск с переиспользованным PID не получает запрос из старой строки. Если macOS не предоставила дату запуска, backend отказывает в отправке.
- В preview запрещены запись закреплений и завершение. Нативный backend дополнительно запрещает завершение при `Snapshot.active`.

## Проверки

`AppQuitPolicyTests` проверяет фильтрацию GUI-приложений, Finder/Hop/self, дубликаты, закрепление разных экземпляров и идентичность запуска. `AppQuitControllerTests` использует только fake backend и отдельный UserDefaults suite: отсутствие автоматического завершения, обновления по событию, сохранение закреплений, индивидуальное и общее исключение закреплённых, устаревшую строку, отказ, повтор и фактический выход.

Тесты написаны до реализации. Сборка и запуск тестов переданы главной сессии, поскольку общий каталог сборки занят параллельной проверкой. Реальные пользовательские приложения не завершались. До завершения интеграции остаются проверка сборки, fake-тестов, визуальная проверка состояний и фактических переносов на всех поддерживаемых языках. Проверка сохранения в стороннем приложении требует отдельного тестового документа; она не проводилась.

Готовый аналог внутри Hop не найден. Существующий private `UninstallController.quitIfRunning` привязан к удалению приложения и синхронному ожиданию; новый блок его не использует.
